# Web loading screen and web frame rate
**Sources:** `GDD.md` (not read: technical brief, no Journal work), `game/export_presets.cfg` (preset "Web", `html/custom_html_shell=""`, PWA off), `game/builds/web/index.html` (`GODOT_CONFIG` fileSizes: `index.pck` 805760 bytes, `index.wasm` 35649444 bytes; loader has a `status-progress` bar driven by `onProgress`), `_tools/build.py` (zips `builds/web` with ZIP_DEFLATED; COOP/COEP smoke server).
**Budget:** 2 of 6 WebSearch, 11 of 12 WebFetch used.
**Request:** (1) what the web loader is doing and which part dominates; (2) threads/SharedArrayBuffer vs no-threads export, and what 4.2 supports; (3) ways to shorten or hide the load; (4) known reasons a gl_compatibility web build runs slower than desktop.

Local fact for context (from our own file, not web): `game/builds/web/index.html` lists `index.wasm` at 35,649,444 bytes against `index.pck` at 805,760 bytes. The engine wasm is about 44 times the game data, so the download of the wasm is the likely dominant part. This is inference from sizes, not a sourced claim.

## Not supported
- Which phase (download, wasm compile, engine init, first-frame shader compile) usually dominates the loader: no page fetched breaks the startup into phases or measures it (the community test repo, github.com/JohannesDeml/Godot-Web-LoadingTest, gives build sizes only, no load times). Only sizes and the forum anecdotes above bear on it.
- WebAssembly compile time as a cause: the forum thread does not discuss it. Not sourced.
- How long the load "should" be: no source gives a target. The only figures are anecdotal (about 15 s with a custom template, forum thread above, unverified verbatim).
- Whether the default Godot 4.2 loader serves or decodes pre-compressed `.br`/`.gz` files itself: a forum report found manual `.wasm.br` failed with the stock loader on itch.io, but I did not fetch that thread. Not supported (budget and fetch not done).
- Single-thread (4.3+) export changes load time: only the docs' "not as performant" statement was sourced (R4). No load-time comparison sourced. 4.2 has no single-thread export (R1); an upgrade is a separate project decision.
- Boot splash setting hiding the load: R12 says the default page does not show the splash; no source on a custom shell showing it. Not supported.
- Why gl_compatibility web FPS is lower than desktop beyond R3, R16, R20, R21 (WebGL 2.0 only, WebAssembly not native, shader compile stalls the render thread, no ubershaders): I found no source ranking these or quantifying them. A forum post on SubViewport scenes dropping below 1 FPS on web (4.3) appeared in search results but was not fetched. Not supported.
- Whether our `vram_texture_compression for_desktop=true, for_mobile=false` setting affects web load or FPS: not searched (budget). Note it is relevant, since mobile browsers are likely.
