# game - the Godot project (Patricia, Bob, Quinn)

One job: turn applied designs into a running Godot game. Godot 4.2.1 (standard build, GDScript), Compatibility renderer, portrait; `scenes/main.tscn` is the Prototype 0 farm scene (hive, flowers, centrifuge, crate, truck and farm UI) under the isometric camera.

Naming (designer, 2026-11-21): `round` is a design or critic round, `run` a re-run of a tool (`run-N/`, never an `-rN` suffix); versions keep their dots (`0.2.1`); dates are `YYYY-MM-DD`; no `now`/`before` folders, use the version or the date.

## Inputs
- Working (this run): the work order in `specs/` (e.g. `specs/prototype-0.md`), or the feature list, layout spec or build request
- Reference (every run): `../GDD.md` (Engine Integration, Technical Constraints, plus the sections the task touches)
- Reference (sections named per agent): `PATTERNS.md`, the game programming patterns that fit this project and their Godot form
- Reference: `RECIPES.md`, step-by-step recipes (add a panel, a corner icon, a translated label, a config value with its Dev row, a Dev button, a toast) with their tests; the goal agent attaches the matching recipe to each build brief
- Reference (when cited): `../proposals/design/_index.md` and `../proposals/balance/_index.md`, then only the applied proposals they name

Do NOT load: the review folders, `_meta/agent-runs.md`, proposals still `proposed` or `rejected`.

## Process
1. Build only what the GDD or an applied proposal specifies. If the spec is ambiguous, stop and list the questions.
2. Patricia writes scripts, Bob writes scenes that attach those scripts by path, Quinn tests both. **Tests come from the spec, not the code** (designer, 2026-11-04): Quinn writes them from the approved spec in parallel with Patricia, without reading her in-progress code, and every expected number is read from the config. A test that fails then is a finding against the code or the spec, never a reason to change the test to match the code. Every interaction that keeps running gets one sequence test: start, leave mid-way by every exit (including app pause: the player's input stops counting, while anything automatic finishes on its own: loads and pours, and whatever an owned automation upgrade runs), come back, do it twice; where the spec is silent on leaving, coming back or whether a step goes on by itself, Quinn asks rather than guesses (designer, 2026-11-08; `_tools/goal_agent.py` `INTERACTION_CHECKLIST`). No agent edits another agent's folder.
3. TBD balance values stay as marked placeholders in exported variables or config resources. Every tunable value lives in the config (never a literal in a script), is read when used rather than cached, and is adjustable live in the in-game **Dev mode** panel (`scripts/dev_panel.gd`). Every spec includes Dev mode and adds its new values to it (designer, 2026-11-04).
4. **Steps, not batches** (designer, 2026-11-04). A milestone's spec is built in small steps, each ending green and playable (e.g. 0.1a refactor with no behaviour change, 0.1b, 0.1c). Work happens on `main` (milestone branches dropped, designer 2026-11-21) with a checkpoint commit after each green step (`_tools/checkpoint.py`, goal_agent), so each agent's diff can be reviewed and one step undone without losing the others. Origin gets a push only when the full suite is green, with the designer's yes; a milestone the designer has played, or an assignment's demo build, gets a tag (`v0.2.1`, `a6-demo`). The designer plays the build at the end of each step, not only at the end of the milestone.
5. **Contract and parallel start.** Node names are the contract between Patricia and Bob. The spec names them, including inside prop scenes; when Patricia must confirm or adjust them, she writes that section first, as its own short handoff, and Bob starts from it while she writes the scripts. `python -I _tools/contract_check.py` checks every `find_child`, `get_node`, `$` and `%` lookup and every scene `NodePath` against the scenes, without Godot; it runs in the pre-commit gate, and Bob and Patricia run it before handing off.
6. **Visual checks before Quinn.** Bob renders a fixed shot set: one screenshot per state in the spec's state table plus any new view, not only the starting state. The visual style loop, `python -I ../_tools/style_loop.py <slug>` (`tests/style_shots.gd` renders the shots, `_tools/style_check.py` measures the script rules, Vera judges the rest), compares them with `../STYLE_GUIDE.md` and Bob refines until it passes or stops for the designer; the orchestrator still checks the shots against the spec. **Look before done** (designer, 2026-11-08): passing tests never make a scene change done. In a goal-agent run every Bob change gets one style-loop round, and a spec item naming a picked variant (`scenes/variants/<prop>-r<N>/<prop>-r<N>-<x>.tscn`; older rounds sit in unnumbered folders) beside the live prop (`scenes/props/<prop>.tscn`) gets a pick match: `_tools/pick_match.py` renders both in one load and Vera judges only whether they match; either FAIL goes to Bob in the fix round. By hand: `python -I ../_tools/pick_match.py <live> <pick> --no-agent`, then look at both shots.
7. **Snapshot tests for "do not change".** Whatever the designer marks as not to change (e.g. the comb pop) gets reference frames recorded once from the last approved build and compared on every build (pixel tolerance stated in the spec), not only its parameters.
8. **Scripts before tokens** (designer, 2026-11-04). Deterministic work runs as a script, and agents read its summary. Rex, the Script Runner (`.claude/agents/script-runner.md`), runs full suites, `--refresh` runs, builds, `mutate.py` and shot scripts, dispatched by the orchestrator; Quinn writes tests and runs only his own with `godot_run.py unit --only <names>` (designer, 2026-11-05). The scripts: `_tools/godot_run.py` (test suites; raw logs to `reports/_runs/`, gitignored), `_tools/build.py` (version, exports, web zip, smoke test), `_tools/mutate.py` (named mutations in `tests/mutations.json` prove each new test fails for the right reason), `_tools/contact_sheet.py` (one image of a shot set), `_tools/model_snap.py` (scene or part shots and upgrade icons). Tests are split one file per area. Agents get only the spec sections their task needs (the orchestrator names them in the brief; Clarifications are folded into the spec body when a build closes) and reply in at most 150 words. A milestone starts in a fresh orchestrator session, carried over by the session-handoff memory.
9. **Fixes.** The owner of the folder fixes its bugs: Patricia `scripts/`, Bob `scenes/`, Quinn `tests/`. The orchestrator (the main session) may fix a bug itself only when the diagnosis is certain and the fix is a few lines; anything larger goes back to the owner with Quinn's report. Whoever fixes it, every fix is recorded: a **Fixes** section in the report names the bug, its owner and who fixed it, the bug is counted in the Rework tally in `../_meta/team.md`, and Quinn's tests are re-run before any build is exported.
10. **One folder, worktrees only when needed** (designer, 2026-11-06: "it's difficult to navigate the workspace with this worktree stuff"). Before dispatching agents, the orchestrator decides where they work. The default is the main folder on `main`. A worktree (`git worktree add .claude/worktrees/<name> <branch>`) is used only when two sessions or agents must change the same files at the same time, or when a long run (tests, build) must keep going while other work changes the files it reads. While a goal run is live, the main session never edits its files (`scripts/`, `scenes/`, `materials/`, `tests/`, `specs/`) in the main folder: it edits in a worktree and merges after the run (designer, 2026-11-08; `_tools/guard_shell.py` rule 6 refuses it while `_meta/usage/goal-run.lock` exists). The brief names the folder. When the worktree's branch is merged into `main`, the orchestrator removes the worktree and deletes the branch the same day. A fresh worktree needs `godot_run.py ... --refresh`, and it takes `_tools/` fixes from `main`.

## Outputs
- scripts, scenes and tests -> their folders above
- `report.md` -> `reports/builds/<version>/`

## Check
Quinn's report passes (tests green, 60 FPS on the test devices), then the developer reviews the git diff and plays the build.
