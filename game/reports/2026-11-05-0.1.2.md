### The 6 fixes to the Clarifications (all my tests)

| Test | Was wrong | Now |
|---|---|---|
| `t_hive_footprint_and_frames` | frames in a row along Z | frames in a row along X: gaps between sorted X > 0.05, all share one Z (spread <= 0.05) |
| `t_jar_fills_then_lid` | read the hidden `SpigotJar` | every visible jar is sampled per frame; the jar showing honey between 0.3 and 0.7 with no lid is the one under test (by position and look). The fill time must be `bottling_seconds_per_jar - jar_fly_seconds` after the jar arrives |
| `t_zoom_view_option_a` | whole bucket rim (4 corners) on screen | removed; `BucketMouth` on screen and not under Back stays (already there) |
| `t_jar_flights_to_spigot_and_truck` | fill = full `bottling_seconds_per_jar` after arrival | fill = cycle minus `jar_fly_seconds` (1.5 - 0.8 = 0.7 s) |
| `t_jar_lands_in_crate_when_truck_away`, `t_crate_fulls_fly_to_truck_on_return` (and `t_jar_flights_to_spigot_and_truck`) | timed a flight from the last sample inside the origin zone to the first inside the destination zone (a crate disc 2 units wide: 0.19 s measured for a 0.8 s flight) | `_cut_flight` now walks the start back to where the jar last stood still (< 0.003 per frame) and the end on to where it rests (within 0.01 for 0.1 s). `t_flight_judge_can_fail` got 2 checks that prove it: a 1.4 s flight into a big zone is still a problem, a 0.5 s one is not |

I checked the real code behind the flight tests: the trace of the spigot-to-crate jar moves from 1.01 s to about 1.8 s (the full 0.8 s); the old measure was the test's fault.

### Gap found and closed

The mutation "wheels turn at half speed" was **missed** by both `t_truck_wheels_roll_with_travel` (it checks the sign of the roll only) and `t_wheel_rims` (checks the mark follows the wheel). I added a check to `t_truck_wheels_roll_with_travel`: the wheel turns path / radius radians within 15 percent (radius from the wheel's cylinder and scale). It passes on the real code and the mutation now fails it.
